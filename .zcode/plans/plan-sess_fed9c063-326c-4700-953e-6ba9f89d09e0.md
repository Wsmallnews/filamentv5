# 通用全局搜索系统 —— 最新实施计划

## 范围与已确认决定（沿用此前逐条确认的结论）

- **出口**：本次只做前端 Livewire 搜索组件（`sn-support-components-search`）；Filament 后台 Provider 将来一个类接入。
- **双引擎**：默认 `database`（WHERE LIKE，零依赖，对中文友好），可配置 `scout`（复用 Laravel Scout 驱动体系）；引擎接口预留 fulltext 等扩展。
- **多搜索实例**：搜索名 = 插件 ID（`app(CmsPlugin::class)->getId()` → `sn-cms`），cms/shop 各有独立搜索互不污染；`imports()` 组合（shop = cms + product）。
- **引擎指定级别**：每次注册（搜索名）时指定，未指定走全局配置兜底 `database`。
- **目录**：全部收进 `addons/support/src/Features/Search/`（不建顶层 Search 目录）。
- **字段默认剔除关联字段**：默认取 `$keywordSearchFields` 并剔除含 `.` 的关联路径字段（前端搜的是资料实体，默认不做关联查询）。
- **适配链接架构变化**（v5 后落地的新链接机制）：搜索结果 URL 仅由**注册 source 时的 `url` 闭包**提供（注册包即调用方，直传闭包，与被否的 HrefRegistry 无关）；无 url 的来源渲染为无链接项；前端搜索组件永不产生 panel 地址。标题/描述/封面仍默认取 `HasSnSubject` 固有数据方法（契约现仅剩 4 个方法）。


## 二、核心 API

```php
// —— 注册（各包 packageBooted()，搜索名 = 插件 ID，第三参 = 搜索级配置）——
Search::registers(app(CmsPlugin::class)->getId(), [
    ['key' => 'post', 'model' => Utils::getPostModel(),
     'query' => fn ($q) => $q->published(),
     'scopeable' => Utils::getScopeable(),
     'url' => fn ($record) => Utils::route('posts.show', $record)],  // 前端详情链接（slug 路由已存在）
], ['engine' => 'scout']);       // cms 用 scout；不传则全局兜底 database

Search::registers(app(ProductPlugin::class)->getId(), [
    ['key' => 'product', 'model' => Utils::getProductModel(),
     'query' => fn ($q) => $q->where('status', ProductStatus::Up)],  // 无 url → 无链接项
]);

// shop 包（或 app）：组合搜索，并为导入来源覆盖 url 等
Search::imports('sn-shop', [
    'sn-cms',
    'sn-product' => ['url' => fn ($record) => shop_product_route($record)],
]);

// —— 查询 ——
Search::search('关键词');            // 所有搜索来源合并（union）
Search::search('关键词', 'sn-cms');  // 仅 sn-cms 的来源；未知搜索名抛异常（fail-fast）
```

### SearchSource 选项

```php
[
    'key' => 'post',                        // 默认 morph 别名/类名
    'model' => Post::class,                 // 必填，支持 morph 别名
    'group' => '文章',                      // 默认模型 label（getModelLabel → morph → 类名 headline）
    'fields' => ['title', 'description'],   // 默认 resolveKeywordSearchFields() 剔除含 '.' 的字段
    'limit' => 8,                           // 默认 config('sn-support.search.results_limit')
    'sort' => 1,                            // 来源排序
    'query' => fn (Builder $q) => ...,      // LIKE 引擎：状态/业务过滤
    'scout' => fn (Scout\Builder $b) => ...,// Scout 引擎：索引过滤（此时 query/scopeable/fields 不生效）
    'scopeable' => ['scope_type' => ..., 'scope_id' => ...],  // LIKE 引擎：scope 过滤
    'title' / 'description' / 'cover' / 'badge' => fn (Model $r) => ...,  // 默认取 HasSnSubject 固有方法
    'url' => fn (Model $r) => ...,          // 仅注册方/imports 覆盖方提供，默认无链接
    'visible' => fn (): bool => true,       // 来源是否参与本次搜索
    'results' => fn (string $query): Collection => ...,   // 高级：完全自定义，绕过引擎
]
```

### 类要点

- **SearchRegistry**：`register()/registers($search, $sources, $config)/imports($search, array $searches)/forget($search)/search($query, ?string $search = null)`。空关键词返回空；`visible()` 为 false 跳过；来源注册时戳上所属搜索的 engine（imports 保留原引擎，覆盖项可改），未指定的查询时读全局配置；引擎解析 `'database'`/`'scout'`/类名（须实现 `Engine`），`'scout'` 先 `class_exists(\Laravel\Scout\EngineManager::class)` 守卫，未装抛带安装指引的 `SupportException`。
- **Engines\Engine**：`search(SearchSource $source, string $query): Collection<Model>`。
- **DatabaseEngine**：`$model::query()` → scopeable 过滤（模型有 `scopeScopeable` 时）→ 来源 `query` 闭包 → 空白拆词（`split_terms`，多词 AND、字段间 OR）→ 原生 `whereLike($field, "%term%", caseSensitive: false)` → `->limit()`。
- **ScoutEngine**：校验模型 use `Laravel\Scout\Searchable`（字符串 `class_uses_recursive` 检查，缺 trait 抛带指引异常）→ `$model::search($query)` → 来源 `scout` 闭包 → `take($limit)->get()`。
- **SearchResult**（readonly）：`key, group, title, description, coverUrl, url, badge, morphType` + `toArray()`。

## 三、support 包修改文件

1. `SupportServiceProvider`：`packageRegistered()` 注册 `SearchRegistry` 单例；`packageBooted()` 加 `Livewire::component('sn-support-components-search', ...)`。
2. `config/sn-support.php` 新增：
   ```php
   'search' => [
       'engine' => 'database',   // 全局兜底引擎：'database' | 'scout' | 类名
       'results_limit' => 8,
       'split_terms' => true,
       'case_insensitive' => true,
       'debounce' => '300ms',
   ],
   ```
3. `src/Support/Utils.php`：加 `getSearchConfig(?string $name, $default)`。
4. `composer.json`：aliases 加 `"Search": "Wsmallnews\\Support\\Facades\\Search"`；`suggest` 加 `laravel/scout`。
5. `resources/lang/{zh_CN,en}/search.php`：`placeholder`、`empty` 等。

## 四、前端 Livewire 组件

- `src/Livewire/Components/Search.php`（继承 `Wsmallnews\Support\Livewire\Base`，use `HasProperties`）：`public ?string $query`、`public ?int $limit`、`public string $placeholder`（默认 lang）；`getResultsProperty()` → `Search::search($this->query)`。组件不感知引擎与搜索名组装细节。
- 视图 `livewire/components/search.blade.php`：Alpine 控制聚焦展开/收起、`wire:model.live.debounce.300ms`（读配置）；分组渲染（每组标题 + 行项：可选封面、标题高亮命中、描述）；有 url 渲染 `<a>` 否则 `<div>`；空态复用 `x-sn-support::empty-state`。用法：`<livewire:sn-support-components-search placeholder="搜索..." />`。

## 五、依赖与接入

- 根项目 `composer require laravel/scout`（唯一依赖变更，用于 scout 引擎跑通与测试）；support 仅 `suggest`，不强制包使用者安装。
- **Scout 模型侧约束**：模型需 use `Laravel\Scout\Searchable`，PHP trait 无法条件引入，包内模型不加（避免硬依赖）；项目可通过 `config('sn-cms.models.post')` 等替换为 use 了 trait 的子类（生态已有的模型替换扩展点）。本应用先在 `app/Models/User.php` 加 `Searchable` 作示例。
- **各包接入（每个一行注册）**：cms 注册 `post` 来源（url 闭包给 `posts.show`）；product 注册 `product` 来源（query 过滤 `ProductStatus::Up`，无 url）；app `AppServiceProvider::boot()` 注册 `app` 搜索（User 来源，`'engine' => 'scout'`，演示框架层模型 + 指定引擎）。

## 六、测试（根项目 `tests/Feature/Support/`，造数参照现有测试）

1. **SearchRegistryTest**：多搜索注册/组合（imports 带覆盖）/`forget`/排序；union 与指定搜索名筛选；引擎戳记（imports 保留原引擎、未指定走全局兜底）；`visible=false` 跳过；未知搜索名抛异常。
2. **DatabaseEngineSearchTest**：LIKE 命中 title/description；拆词 AND、字段间 OR、大小写不敏感；含 `.` 的默认字段被剔除；limit；分组与排序；`scopeable`/`query` 过滤；空关键词；`results` 闭包绕过引擎。
3. **ScoutEngineSearchTest**：`config(['scout.driver' => 'collection'])`（无需外部服务）；User（已加 trait）命中、limit、`scout` 闭包过滤；未加 trait 的模型抛 `SupportException`。
4. **SearchComponentTest**：`Livewire::test('sn-support-components-search')` 渲染、填 query 后断言结果与空态、无 url 来源渲染 div（不含 panel 地址）。
