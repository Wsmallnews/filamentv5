# 内容字段逻辑迁移至 support + 新增 images 纯图类型 + 按模块配置内容类型

## 现状分析

- PostForm 与 NavigationForm 中的 content 处理逻辑**完全重复**：`Group::make()->relationship('content')`（MorphOne → `sn_contents` 表）+ 虚拟字段 `content_{type}` 映射（fill 时 real→virtual，save 时 virtual→real），`mapVirtualContentField()` 在两个文件里各复制一份。
- `ContentType` 枚举（`Wsmallnews\Support\Enums\ContentType`）已有 Textarea/Richtext/Markdown 三个 case，带 label/color/icon。
- `sn_contents` 表由 support 包提供（morphOne 多态），**无需新迁移**；product 模型已有 `content()` 关联。
- product 目前是**手动方式**处理 content：CreateProduct/EditProduct 页面中捕获脱水数据 + afterSave 里 `updateOrCreate`（`content_type` 硬编码 `'richtext'`），详情可选（空则不创建/删除）。
- cms 根配置 `config/sn-cms.php` 会完全覆盖包内配置，两份需同步修改；product/support 配置仅存在于包内。
- 无旧数据，不做旧 content_type 兼容处理。

### 2. FormComponents 新增 contentTypeGroup() 工厂方法
`addons/support/src/Filament/Forms/FormComponents.php`：

```php
public static function contentTypeGroup(
    ?string $configKey = null,            // 模块配置键，如 'sn-cms.contents.post'
    ?array $types = null,                 // 允许类型（覆盖配置）
    ?ContentType $defaultType = null,     // 默认类型（覆盖配置）
    string $relationship = 'content',
    ?string $label = null,                // 内容字段标签覆盖（默认 sn-support 翻译"内容详情"）
    ?string $directory = null,            // 编辑器附件 / 纯图上传目录
    bool $required = true,                // 内容是否必填
): Schemas\Components\Group
```

- **类型解析优先级**：显式参数 > `config("{$configKey}.types"/"default_type")` > `sn-support.form_components.content` 全局默认 > 全部 cases / Richtext。
- **组件结构**：`Group->relationship()` + 三个 mutate 回调（迁移现有逻辑并泛化）+ schema：`ToggleButtons content_type`（live、inline grouped，options 直接使用允许类型列表）+ `Hidden content` + `content_textarea` / `content_richtext` / `content_markdown` / `content_images` 各自按 `$get('content_type')` visible，**仅渲染允许类型**对应的编辑器字段，不允许的不进 schema。
- **images 存储**：`sn_contents.content` 存 JSON 路径数组；fill 时 `json_decode` 回填给 `localImageUpload('content_images')->multiple()`，save 时 `json_encode`。不采用 Spatie 媒体库（Content 模型未实现 HasMedia，且媒体挂在 content 记录上层级不合理）。
- **单类型时**（如 navigation 只有 markdown）：ToggleButtons `->disabled()->dehydrated()`，映射回调对缺失的 content_type 有 `?? $defaultType` 兜底。
- **normalize**：content_type 兼容字符串（fill）与枚举（save）两种形态。
- **可选模式空白语义（完全封装在组件内部，页面零代码）**：`required: false` 时，空提交不创建 content 记录、编辑清空则删除已有记录。实现全部位于 contentTypeGroup 内部——优先 mutate 回调返回 `null` 阻止创建（同 Repeater 语义），若 Group 不支持则改用 `saveRelationshipsUsing()` 自定义保存闭包（blank→delete，否则 updateOrCreate），以测试验证落地。调用方永远不需要在 Create/Edit 页面写任何 content 处理代码。
