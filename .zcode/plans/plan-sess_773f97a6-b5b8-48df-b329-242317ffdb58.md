# 定时任务系统实现方案（v3 最终修正版）

## 核心设计

建立 `sn_scheduled_tasks` 表（多态关联任意实体），`ScheduledTaskRegistry` 是唯一中枢——各包注册 `{action, label, forms, handler, visible}` 五件套，自动驱动表单选项 + 自定义字段 + 执行处理器 + 状态互斥。

**关键决策**：表名 `sn_scheduled_tasks`；注册键按 morphType 分组（`sn_post`/`sn_product` 天然隔离）；多实体各自单独注册；表单用 Repeater + `->relationship()`；状态互斥按 action 逐个过滤；price_change 本次仅预留；直接改现有迁移删字段；**现有 `ScheduleHelper.php` 不动**。

5. **Facade** `src/Schedule/Facades/ScheduledTask.php`（accessor = ScheduledTaskRegistry::class）

6. **Command** `src/Commands/RunScheduledTasksCommand.php`
   - signature `sn-support:run-scheduled-tasks`
   - 扫描 `ScheduledTask::due()` → 按 `schedulable_type`+`action` 找 handler → 执行 → 更新 status/executed_at/result

## 关键设计说明

1. **Registry 统管一切**：注册 `{action,label,forms,handler,visible}` 一次，表单 Repeater 的 action 选项 + 动态字段 + Command 执行器全自动。各包只和 `ScheduledTask` Facade 打交道。

2. **模块隔离靠 morphType**：`sn_post` vs `sn_product` vs `sn_navigation`，morph 别名是天然命名空间。cms 的 Post 和 Navigation 各自注册，不串。

3. **多实体注册**：每个实体单独 `ScheduledTask::registers('sn_xxx', [...])` 调用。

4. **状态互斥**：visible 闭包接收当前 status 字符串，Registry 的 filterVisibleActions 自动过滤。如 status=Up 时不显示"定时上架"。

5. **现有 ScheduleHelper.php 不动**：它保持通用调度频率配置职责（Comment 审核等也用）。Command 注册调度时复用它的 `configure()` 方法。

6. **price_change 半完成**：注册了 forms + 预留 handler，表单可用，多规格改价待 SKU/Variant 完善后实现。
