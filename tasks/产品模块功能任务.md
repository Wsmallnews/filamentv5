## 4. 四种规格类型的需求

产品表单中通过 `spec_type`（ToggleButtons）切换以下 4 种模式，切换时 `live()` 联动显示对应区域。

### 4.1 单规格（Single）

- `sn_product_variants` 的字段（价格、库存、货号、重量等，见 3.2 变体表）**平铺显示在产品 Form 中**：可用 Section/Fieldset 包裹，但必须是一级字段（非嵌套在 repeater 里），用户无需感知"变体"概念。
- 保存时写入 `sn_product_variants` 表（该产品只有一条变体记录，`spec_type = single`）。
- 已有字段方法（3.4 节）可直接复用。

### 4.2 多规格（Multiple）

涉及 `sn_product_specs` + `sn_product_variants` 两表，需完成规格组合。

**规格定义区（父级 spec）：**
- 使用 Filament v5 的 `Repeater` 表单。
- 父级 spec 每项只填一个名称（如：颜色、尺码）。

**规格值区（子级 spec）：**
- 使用 Repeater 的 **table 模式**。
- 每行支持：设置名称 + 上传图片（对应 `sn_product_specs.name/image`）。

**变体组合区（variants SKU 组合）：**
- 使用 Repeater 的 **table 模式**。
- 当规格定义变更时，spec repeater 设置**延迟 live**（参考项目规范：优先 `live(onBlur: true)` 或 debounce，避免每键刷新），触发重新计算笛卡尔积，刷新 variants 列表。
- 已存在的 variant 记录尽量保留用户已填的值（价格/库存等），只增删变化的组合。

### 4.3 主多规格（MainMultiple）⚠️ 待决策

> 本质：多规格的快捷方式——只需在"主规格"上统一设置变体属性（价格、库存等），variants 列表只读显示，无需逐行填写。

需求描述：
- 在主规格上编辑属性（价格、库存等），variants 列表中这些字段**只读展示**主规格设置的值。
- 保存时：将主规格上设置的属性同步到所有 variants 记录。
- 编辑时：反向把 variants（取第一条或聚合）的属性值提取回主规格表单展示。
- （可选方向）评估是否真的需要在主规格上冗余这些字段。

**🔴 决策点（必须先回答用户，再实现）**：
请评估 `MainMultiple` 类型是否必要——参考主流开源电商系统（它们通常没有独立的"主多规格"类型，而是通过"批量填充 variants"按钮实现同样的效率目标）。给出结论：
- 若不必要 → 建议用户删除该枚举 case，改用"多规格 + 批量填充功能"方案；
- 若保留 → 说明理由并按上述需求实现。

### 4.4 多单位（Unit）

> 本质：只有一个规格项的多规格，规格值 = 单位名称（如：瓶、箱、件）。

- 因为只有一个规格项，**父级规格名称固定不可修改**（如固定为"单位"）。
- 逻辑与多规格基本一致。
- 差异点：variants 上每个单位需设置 `stock_convert_num` 字段——即当前单位与 `sn_products.stock_unit`（基准单位）的换算比例。
  - 例：product 的 `stock_unit` = 瓶（基准），当前 variant 单位 = 箱，1 箱 = 10 瓶，则该 variant 的 `stock_convert_num` = 10。

## 5. 技术约束与项目规范（必须遵守）

- 环境：PHP 8.4 / Laravel 13 / Filament v5 / Livewire v4 / Pest v4（见根目录 `AGENTS.md`）。
- Filament 规范：
  - `Repeater` 用 `->schema()`，不是 `->fields()`。
  - 响应式字段优先 `->live(onBlur: true)`，避免每键更新；`afterStateUpdated` + `Set` 实现联动重算。
  - 布局组件（`Section`/`Grid`/`Fieldset`/`Repeater`）默认不占满整行，需要显式 `->columnSpanFull()`。
  - 上传组件优先使用 support 包工厂 `FormComponents::mediaImageUpload()` 等（自动应用 disk/visibility 默认配置）。
  - Action 命名空间一律 `Filament\Actions\`。
- 价格字段使用 `MoneyCast`（`sn_product_variants.price` 已是分存储整数）。
- 新建文件优先用 `php artisan make:` 命令并传 `--no-interaction`。
- **每个变更必须写 Pest 测试**并运行：`php artisan test --compact --filter=...`（Filament 表单测试用 `livewire()` + `fillForm()/call()` 断言）。
- 改动 PHP 文件后运行：`vendor/bin/pint --dirty --format agent`。

### 实现要点备忘（后续 agent 请阅读）

- **组合指纹用「排序后的子规格名称」**（`ProductSpecForm::variantFingerprint`），不用 repeater item key——Filament repeater 在 hydrate/dehydrate 时会重写 key。
- **页面钩子用 `afterCreate`/`afterSave`（v5 为 callHook 直调，无 parent 实现），规格数据从 `form->getRawState()` 读取**（dehydration 阶段 visible 闭包求值不可靠）；`content`（富文本）在 mutate 阶段捕获脱水值后写入 `sn_contents` morphOne。
- **价格链路**：表单元（decimal string）→ `ProductSpecService::normalizePrice()` → `MoneyCast::set`（内部 ×100 转分）→ DB 分；读取走 `MoneyCast::get`（Money 对象）→ `formatByDecimal()`。
- **新增依赖**：`cknow/laravel-money`（MoneyCast 所需，原先缺失）、`pestphp/pest-plugin-livewire`（dev，Livewire 表单测试）。
- **迁移**：root `database/migrations/2026_08_18_000001~000003`（specs 表、variants+pivot 表、`sku_type`→`spec_type` 安全改名），已执行到开发库；addon stub 同步。
